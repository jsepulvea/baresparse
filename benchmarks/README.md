# Reproducible sparse benchmark

`fixtures/structured.h` is an original, MIT-licensed **structured synthetic**
problem, not a measured physical-model Jacobian. It is a 4-row, 8-column
rectangular grid numbered by grid rows (`i = 8*y+x`), with a nonsymmetric
five-point stencil and no periodic boundary edges. CSC generation visits
columns then increasing row indices. There are 32 unknowns and 136 structural
entries; identity LU stores 199 strict-L and 231 U entries (430 total).

For sequence step s = 0..63, every diagonal is `6 + s/128`; an off-diagonal
entry is `-0.75` when row < column, `-1` otherwise. The known solution is
`x_i = 1 + i/32`. RHS is generated by CSC multiplication in single precision.
All constants are dyadic; the procedure and values are preserved exactly in
source. The declared pattern stays fixed for all steps. This strictly
diagonally dominant family is intended to exercise repeatability and sparse
fill, not challenge fixed-pivot robustness.

The benchmark queries and checks the exact buffer capacities, analyzes once,
warms up four times on step zero, then records 64 refactor/solve pairs. Every
warm-up and measured solve passes both a known-solution relative error check
and normwise backward error, each at `64*FLT_EPSILON`. Residual accumulation
uses double outside timed work. Guards surround symbolic/factor/work buffers.
The source contains no runtime allocation. All benchmark memory is in a
caller-owned `brsp_bench_context`, distinct from the library's memory needs.

## Host reproduction

```sh
cmake --preset host-release
cmake --build --preset host-release
./build/host-release/benchmarks/brsp_benchmark_sparse > build/host-sparse.csv
python3 scripts/summarize-benchmark.py build/host-sparse.csv > build/host-sparse-summary.json
```

Host timing uses POSIX CLOCK_MONOTONIC nanoseconds reduced modulo 2^32, so each
interval must be shorter than 4.29 seconds. OS preemption is uncontrolled. These
are **host results**, never evidence of MCU performance. The older dense
benchmark remains a scaffold/reference utility and is not used to claim speedup.

## Board reproduction and submission

Follow the [F28P55x terminal workflow](../platforms/ti/f28p55x/README.md).
The summary script rejects missing/duplicate samples, incomplete runs, and
numerical failures. It reports observed minimum, median and maximum separately
for refactorization and substitution. Raw error columns are conservative
upper bounds rounded upward to units of 1e-12. It converts C byte counts using
`CHAR_BIT` to eight-bit octets; KiB means 1024 octets. Stored L counts exclude
the implicit unit diagonal. Solver struct sizes, original CSC, residual scratch,
records, guards and benchmark state are included in context size but not factor
or numerical-work sizes. Report them separately; do not add context size to its
included factor/scratch buffers.

Save a result directory containing the raw CSV, JSON summary, source revision,
firmware/image checksum, compiler and programming-tool versions, SDK revision,
exact compile commands, clock/interrupt/code/data placement, link map, code size,
and board reset/power-cycle observations. Allocated stack comes from the linker;
state explicitly whether stack usage was measured. Publishing a measured
high-water mark requires describing its instrumentation. The default benchmark
does not measure stack usage. Never call the maximum observation WCET or claim
a speedup without a comparable measured baseline.

No hardware measurements are available yet. Results may be added to `results/`
only after running the actual experiment; do not fill missing fields with
estimates presented as measurements.
